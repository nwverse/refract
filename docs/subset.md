# SwiftUI subset contract v0

This is the conformance contract for the phase 1 settings-screen slice. It defines accepted source, the native output
an expert would write, and the diagnostic for rejected input. It is not a claim that a backend already implements an
entry: `Fixtures/Corpus.json` records implementation status explicitly. The golden files are hand-written references,
never output copied from the generator being tested.

`docs/GOALS.md` is binding. A missing mapping, an ambiguous translation or a loss of observable semantics is a
build-time error, never an approximate native view. All output calls platform APIs and application-owned code only;
there is no Refract runtime, base view, interpreter or lookup registry in a generated application.

## 1. Source and generated-file conventions

  input. If the file declares a generated child `View` with only declared model interfaces and one immutable
  `Identifiable` item input, a parent list row can call it with explicit labels. The child retains its native
  composable/component boundary and its own item-local scope. Recursive direct or indirect child calls are errors.
- One `Input.swift` contains one `struct <Name>: View` with a `body`, plus any `Identifiable` item type, model
  protocol or `RefractNativeView` declaration that it needs. The native marker and interop helpers are ordinary
  SwiftUI source declarations specified by `docs/interop.md`, not a linked library. `import SwiftUI` is the only
  import in v0. A screen name and its item/protocol names are valid ASCII Swift identifiers beginning with an
  uppercase letter. File order determines declaration output order. A generated View, model, item, enum or native
  declaration name must be unique within one input; repeated names are rejected with `RFSYN004` before IR construction.
- Multiple `--input` files form one explicit same-module declaration set. A child `View`, model protocol,
  `Identifiable` item or switch enum may be declared in a different supplied file; no directory is searched and no
  process-global registry is used. Each file still emits only its own declarations. Duplicate names across files are
  rejected with `RFVIEW007`; missing types, mismatched child inputs and direct/indirect recursion remain errors.
  Child arguments retain the existing model/item contract. Cross-file Kotlin references use the configured package;
  ArkUI imports the sibling output by basename (`./ChildRow`). Inputs and generated outputs must therefore retain
  unique flat basenames, otherwise `RFVIEW008` rejects an ambiguous import path. A future nested-output layout needs
  an explicit path-mapping contract rather than guessed relative imports. Type resolution is independent of input
  order. Recursion diagnostics, however, start from the first input View that reaches a cycle, so the reported
  rotation of that cycle and its declaration location follow the explicit input order; this is not a claim of
  order-independent diagnostics. A lazy-list IR node binds its owning model protocol explicitly. Shared catalogs
  deduplicate only the same declaration identity (source file, source position and name); a same-named declaration
  at another location is an ambiguity error, never a first-wins fallback.
- Stored properties are restricted to `let` item fields, the state and model forms in section 5, and computed `body`.
  Initializers, methods, nested functions, property observers and arbitrary computed properties are outside v0.
- Source expressions are references, literals, list element access, typed construction, comparisons and boolean
  operators documented below. Arbitrary method calls, implicit Swift formatting and reflection are not translated.
- Every generated source starts with `// Generated by Refract; DO NOT EDIT.` and `// Source: Input.swift`.
  Generated Kotlin uses package `refract.generated`, four-space indentation and the public entry point
  `@Composable public fun <Name>(..., modifier: Modifier = Modifier)`. The caller's modifier applies to the root
  view/container; source modifiers follow it, so call-site layout and semantics cannot be silently ignored. Generated
  ArkTS uses two-space indentation, explicit types and `@ComponentV2 export struct <Name>`. Neither component is an
  application entry point; in particular, generated ArkUI has no `@Entry`. Native hosts construct or call components
  directly. ArkUI has no invented cross-platform modifier parameter: callers use native component attributes.
- Default configuration emits `Text` through Material 3 on Android and through ArkUI's `Text` on HarmonyOS. Tokens and
  native components use the project's statically resolved `refract.json`; absent required configuration is an error.
  The JSON schema and resource-catalog validation are owned by the mapping and localization workstreams.
- Source string keys are canonical lowercase ASCII dot-separated segments, for example `settings.item.count`.
  Replace each `.` with `_` to obtain the resource name used by BOTH `R.string.<name>` and
  `$r('app.string.<name>')`. Underscores and hyphens are forbidden in a source key, so distinct keys cannot silently
  alias to one native name. Both catalogs must declare the key and compatible arguments before output is emitted.
- A `Text("...")` string literal is a localization key, not user-visible literal text. Use `Text(verbatim: "...")`
  for intentional literal text. Formatted view text uses ordinary SwiftUI `LocalizedStringKey` interpolation; its
  static parts form the resource key and each supported scalar interpolation becomes one ordered argument. For
  example, `Text("settings.item.count\(model.count)")` maps to a `settings_item_count` resource with `%1$d`.
  Display punctuation, whitespace and prose such as ` items` belong in that resource value, not in the source key.
  Dynamic keys, unsupported interpolation and implicit string conversion are errors. Android and HarmonyOS resource
  files declare compatible one-based positional `%s`, `%d` or `%f` placeholders. `String(localized:)` follows the
  same resource-key rule for supported non-view arguments; no unverified platform overload is part of the subset.
  Per-platform literal text uses `Text(verbatim: refractValue(ios:android:harmonyOS:))` with a string literal in
  every branch; the bare localized form `Text(refractValue(...))` is rejected because iOS would reinterpret the
  selected string as a localization key, diverging from the verbatim native output (see `docs/interop.md`).
- Expected output contains only necessary, alphabetically sorted imports. No backend may introduce a dependency
  merely to share formatting or utility code between outputs. Whitespace is significant in golden comparisons.

## Bounded typed Markdown

`refractMarkdown` accepts a literal version-1 structural AST for paragraphs, inline emphasis, inline code, a bounded
HTTPS link and fenced-code equivalents. It does not accept Markdown source, HTML or runtime document input. The
versioned node forms, stable identities, model-owned link action, resource provenance and native evidence limits are
specified in `docs/markdown.md`; its `RFMD001`–`RFMD018` diagnostics reject constructs outside that slice.

## 3. Modifiers

Modifiers retain their visual meaning. On Compose, source modifiers are appended to the caller's root modifier in
source order, except where lowering two source modifiers into one native operation is necessary for equivalent
semantics. In particular, `.background(color).cornerRadius(radius)` becomes `background(color, RoundedCornerShape(radius))`
so the background itself has the requested rounded shape. On ArkUI `.backgroundColor(color).borderRadius(radius)`
sets the background's corner radius directly; these attributes are not Compose-style ordered modifier operations.
A modifier combination that cannot preserve the source semantics is diagnosed.

| SwiftUI form | Compose form | ArkUI form | Semantics and performance |
| --- | --- | --- | --- |
| `.padding(.medium)` | `Modifier.padding(8.dp)` | `.padding(8)` | Uniform padding. The first modifier starts from `Modifier`; later calls chain onto it. |
| `.padding(.horizontal, .large)` | `Modifier.padding(horizontal = 16.dp)` | `.padding({ left: 16, right: 16 })` | Horizontal/vertical insets; start/end semantics must be retained for horizontal text layouts. |
| `.frame(width: 120, height: 44)` | `Modifier.size(width = 120.dp, height = 44.dp)` | `.width(120).height(44)` | Dimensions are scalar dp/vp values. Numeric literals are layout values, not design-token colors or fonts. |
| `.layoutPriority(1)` on a direct `HStack` child | `Modifier.weight(1f)` in the enclosing `RowScope` | `.layoutWeight(1)` | This bounded layout slice supports only a direct HStack child with the integer literal `1`. Nested children, other priorities, repeated priorities and non-HStack receivers are errors. |
| `.labelsHidden()` directly on a supported Toggle | Only `Switch(checked = ..., onCheckedChange = ...)`, with declared native measurement/accessibility modifiers | Only the actual `Toggle`, retaining `onChange`, `.id` and `.accessibilityText` | Hide the visible title without dropping its typed source validation or explicit native accessibility. Repeated application, arguments, a wrong receiver, or an unrepresentable layout receiver is an error. |
| `.fillMaxWidth()` is not SwiftUI; use `.frame(maxWidth: .infinity)` | `Modifier.fillMaxWidth()` | `.width("100%")` | Only the SwiftUI spelling is accepted. It must not be confused with a fixed width. |
| `.background(.surface)` | `Modifier.background(AppTheme.colors.surface)` | `.backgroundColor(AppTheme.colors.surface)` | A semantic color token resolved by the mapping; never an RGB fallback. |
| `.foregroundStyle(.secondary)` | `Modifier` does not change the text call; use `color = AppTheme.colors.secondary` at `Text` | `.fontColor(AppTheme.colors.secondary)` | Text color is passed directly to the leaf instead of adding a draw/layout wrapper. |
| `.font(.title)` | `style = AppTheme.typography.title` at `Text` | `.font(AppTheme.typography.title)` | A declared typography token. Compose text parameters are direct; no new typography object in composition. |
| `.cornerRadius(.small)` | `Modifier.clip(RoundedCornerShape(4.dp))` | `.borderRadius(4)` | Clipping follows the documented native semantics. Shape instances are not cached in a Refract runtime. |
| `.disabled(model.isLocked)` | `enabled = !model.isLocked.value` at the control | `.enabled(!this.model.isLocked)` | This is a view/control property, not a blanket hit-test filter that changes child behavior. |
| `.accessibilityLabel("settings.icon.hint")` | `Modifier.semantics { contentDescription = ... }` with resource text resolved appropriately | `.accessibilityText($r('app.string.settings_icon_hint'))` | Accessibility labels are localized resources and must not be silently dropped. |

### Dynamic type and native control semantics

Generated text must scale with the platform's user font-size preference, and generated controls must preserve
their native accessibility role, value and label. The subset never hardcodes a fixed pixel size on text or
replaces a native control with a static visual approximation.

- **Dynamic type.** `Text` emitted without a font modifier inherits the toolkit default: Compose `Text` falls
  through to `MaterialTheme.typography.bodyLarge` (scalable `sp`), ArkUI `Text` uses the system font size in
  font-pixels (`fp`). `Text` with `.font(token)` resolves the token to a declared typography value; Compose
  tokens map to `MaterialTheme.typography.*` (or any application `TextStyle` whose `fontSize` is in `sp`) and
  ArkUI tokens map to application-owned `Font`/`Resource` values in `fp`. The mapping rejects a typography
  token that does not resolve to a typed reference, so there is no silent fallback to a fixed-size literal.
  The generator does not emit `.fontSize(<fixed>)`, `fontSize(<fixed>)` or any size override on its own;
  size only changes when the source explicitly requests it through the supported `fontSize` modifier path.
- **Native control semantics.** A `Toggle`, `TextField` or `Button` lowers to the platform's real control
  (`Switch`/`TextField`/`Button` on Compose, `Toggle`/`TextInput`/`Button` on ArkUI). The control retains
  its checked/value state and onChange/onClick callback; the visible label, when present, is a sibling
  `Text` reading the same localized resource. `.labelsHidden()` removes the visible title only; it never
  drops an explicit accessibility label. iOS `.accessibilityLabel(...)` and the closed
  `.refractNativeModifier(.contentDescription(...))` operation lower to Compose
  `Modifier.semantics { contentDescription = ... }` and ArkUI `.accessibilityText(...)` respectively; both
  forms require a statically typed `String` value, so an unknown or untyped value is a build-time error
  rather than a silently dropped label. The generated `Icon`/`Image` lowers decorative images with an
  explicit `contentDescription = null` (Compose) or no accessibility text (ArkUI), matching the source
  contract for decorative vs. labeled images.
- **Fixture and evidence.** `Fixtures/accessibility-dynamic-type/` pins the dual-backend lowering of
  unstyled text, typography-token text, native `Toggle` (visible label and `.labelsHidden()` with an
  explicit accessibility label), `TextField` and `Button`. The Android compile gate compiles this fixture
  on every PR, so a lowering that broke either the dynamic-type path or the control-semantics path fails
  the build. Runtime large-text rendering and screen-reader traversal are inspected through the Native
  JVM Compose verification module owned by #163; this contract does not claim device measurements.

`docs/performance.md` is the performance-rule catalog. The structural requirements for these examples are stable
leaf inputs, narrow state reads, remembered scroll/list state, direct modifiers, and no repeated screen-level work.
Any later benchmark result must identify its environment and is not inferred from fixture correctness.

### Sensitive text entry

`SecureField` lowers to the platform's native secure-input control. Obscured display, keyboard and autofill ownership
belong to the platform toolkit; Refract only selects the password keyboard and visual transformation. The generator
never introduces a runtime secret store, an observer that mirrors the bound value, or a wrapper that formats the
secret into another view.

- **Negative disclosure.** Generated Kotlin and ArkTS for a `SecureField` contain no secret literal, no `println` /
  `print` / `Log.` / `console.` / `hilog` call inside the control's builder or `onChange` callback, and no `Text`
  rendering of the bound `String`. The placeholder is a localized resource key resolved through the usual
  string-resource path; it never carries the secret. The negative-disclosure unit tests
  (`composeSecureInputNeverDisclosesSecret`, `arkUISecureInputNeverDisclosesSecret`) pin this contract on every PR.
- **Reveal is explicit and typed.** `.secureReveal($isRevealed)` accepts exactly one projected Bool `@State` or
  `@Binding`. `.secureReveal(.constant(true))`, literals, non-`SecureField` receivers and repeated application are
  `RFSECURE001` errors, so "always reveal" cannot be smuggled in through a constant. Reveal state is ordinary
  SwiftUI ownership; the generator does not impose its own timeout, biometric gate or auto-hide — applications
  that need those wrap the binding in their own model.
- **Autofill ownership.** On Android, Material 3 `TextField` with `KeyboardType.Password` keeps the IME, autofill
  framework and password managers in platform hands; Refract does not register its own autofill service or
  intercept autofill callbacks. On HarmonyOS, `InputType.Password` gives the same ownership to ArkUI. No secret
  ever crosses the Refract boundary in either direction.
- **Source-only evidence and platform limits.** The Android side is verified by `:fixtures:compileDebugKotlin`
  on every PR (JVM, not device). The ArkTS side is verified by golden fixtures only — the HarmonyOS toolchain is
  not available on the generator devbox, so the contract is the documented ArkUI V2 API and the committed
  Expected.ets. The iOS side compiles as ordinary SwiftUI `SecureField` on macOS; not verified on this devbox.
  No device or emulator screenshot or trace is claimed. See `docs/production-readiness.md`.

## 4. Lists, identity and control flow

### Typed items and `ForEach`

A list model is a Swift value type whose `id` is stable for the lifetime of the logical item:

```swift
struct SettingItem: Identifiable {
    let id: String
    let title: String
    let isEnabled: Bool
}

List(model.items) { item in
    Toggle(item.title, isOn: .constant(item.isEnabled))
}
```

V0 accepts `List(model.items)` and `List { ForEach(model.items) { item in ... } }`. `ForEach(model.items,
id: \.id)` is also accepted when the model explicitly adopts `Identifiable` and `\.id` names the same stored identity
property. Both source forms use the same typed `ListItems`/`ModelCollection` IR and native lowering. A `ForEach` must
be the sole dynamic child directly owned by `List`: nesting it, placing it in a stack or `ScrollView`, and mixing it
with static rows are rejected with `RFLIST003`. The id expression must be the stored `String` or `Int` `id` property.
`\.self`, another property, object identity, array offsets and UUID creation during a body evaluation are rejected.

Compose emits `items(items = model.items.value, key = { it.id }, contentType = { "SettingItem" })`. The item type is
immutable and list identity is supplied directly to the platform. Do not use an index as a fallback or wrap each
row in a new observable holder. When a generated child row needs a stable row-shape name independent of its model
item type, apply the closed `.refractNativeModifier(.contentType("setting"))` operation directly to that child. Both
canonical List forms preserve the declaration and Compose emits the literal row type. The identifier is lowercase
ASCII, cannot be computed or repeated, and is rejected on page-level children, nested containers and controls.

ArkUI emits `LazyForEach(model.items, (item: SettingItem) => { ListItem() { ... } }, (item: SettingItem) =>
item.id)`. Its model property is a platform `BasicDataSource<SettingItem>`: an application-owned subclass supplies
items and native change notifications, without a Refract adapter or a generated mirror of array state. Compose
exposes the same source collection as `State<List<SettingItem>>`. In-place Swift collection mutation is outside the
v0 contract; replacement/delivery semantics belong to the application model. `LazyForEach` is direct in `List`, and
each row has a `ListItem`. For API 18 and newer, a repeated child may use `@ReusableV2` and, for a finite family of
row shapes, `.reuse({ reuseId: () => "setting" })`. API 12–17 keep V2 observation without this reuse capability;
there is no V1 fallback. Fine-grained `@ObservedV2`/`@Trace` item properties are native optimizations, not a Refract
cache or runtime. A list cannot be represented by eagerly mapping all rows.

A typed projection extends this source to
`model.items.filter { item in category == .all || item.category == category }.sorted { lhs, rhs in lhs.rank < rhs.rank || (lhs.rank == rhs.rank && lhs.id < rhs.id) }.refractProjection(name: "catalogItems")`.
The category is an immutable screen input and the item has a stored property of the same declared no-payload enum,
including `.all`. The sort field and item id are Int; `<` selects ascending and `>` descending, while the explicit id
tie-break always remains ascending. Arbitrary predicates, missing or descending ties and other key types are `RFLIST004`
diagnostics. The iOS support extension returns the filtered/sorted array unchanged.

Compose generates a pure function and remembers it with the actual source list and category; sorting direction is fixed
at generation. Lazy rows retain the original item id. ArkUI exports the equivalent pure function and requires the named
projected `BasicDataSource` on the app model. The application computes and publishes that source and its native data
notifications; Refract does not mirror or synchronize it. `Fixtures/list-typed-projection/` covers descending/tied
ordering and `Fixtures/list-reject-projection-sort/` the unsupported String key. Native JVM tests cover empty, category
filtering, `.all` reset, descending/tied order and preservation of original item instances. No iOS/HarmonyOS native
compilation is implied by those tests.

A paged searchable list uses the same `List(model.items)` contract; it does not introduce a paging collection adapter.
The model exposes typed String search text, loading/error/empty Booleans and `loadNextPage`/`retry` actions. Search
editing accepts the explicit `Binding(get: { model.searchText }, set: { model.setSearchText($0) })` form, with matching
model, String type, `set<Property>` action and setter label checked at build time.
`Fixtures/list-paged-search/` covers the complete source
and both native outputs. Page acceptance, cancellation and replacement are app-owned semantics documented in
`docs/state-and-models.md`; generation never performs requests, invents page identity or accepts index-keyed rows.

The first implemented conditional slice accepts `if`/`else if`/`else` with declared Boolean model, `@State`
or `@Binding` properties. Each condition is emitted directly into the native builder; inactive branches are not
composed, and no `AnyView` or runtime view registry is introduced. A root Compose conditional uses a native `Box`
to forward the caller's modifier without changing the branch children.

An immutable optional scalar screen input (`String?`, `Int?`, `Double?` or `Bool?`) accepts exactly
`if let alias = input { ... } else { ... }`. The alias must be a new name that does not shadow another input or
binding, and the else branch is mandatory. The non-null scalar alias is local to the then branch and cannot escape
it. Nullable model/state/binding values, shorthand bindings, comma conditions, `else if` after a binding, arbitrary
optional chaining and `Optional(...)` construction remain diagnostics. Compose checks `input != null` and introduces
a smart-cast `val`; ArkUI checks both `!== null` and `!== undefined` before a local `const` read. `@Param` supports
these nullable unions, but the unbound input is never used as a non-null scalar.

A `switch` over an immutable `let value: LocalEnum` input accepts a locally declared enum with no inheritance,
raw values or generic parameters. Existing no-payload enums remain native enums. A payload enum has exactly one
unlabeled `String`, `Int`, `Double` or `Bool` payload on every case; mixed payload/no-payload enums are outside this
slice. Each case must appear explicitly exactly once with a matching `case .value(let alias)` binding and a distinct
alias. Default, duplicate/missing cases, wildcard/ignored bindings, casts, `where` clauses, grouped cases, multiple
or labeled payloads, and object-graph/reference payloads are rejected (`RFCTRL003`, `RFCTRL005`–`RFCTRL007`).

Compose represents payload enums as a sealed interface with immutable data cases and uses `when (val subject = input)`
with smart-cast branch payloads. ArkTS uses final case classes with a typed readonly scalar field, a union alias and
`instanceof` narrowing, never `as` or `Any`. Both backends emit native lazy branches in source order, validate the
complete case set before emitting, and preserve local alias scope.

The remaining planned conditional contract is below. It is not a claim that every listed form is implemented:

Conditions beyond the initial Boolean-property slice are planned to support `!`, `&&`, `||`, and
equality/ordering of typed scalar values. Optional unwrapping,
implicit casts and arbitrary predicates are rejected. `if` content is a view branch, never a statement that
mutates state during composition.

### Bounded window-width alternatives

`docs/adaptive-layout.md` defines the typed `WidthSizeClass` compact/expanded input. The shared enum/switch Builder and IR preserve one model and screen-local state across native host resizes; a draft that must survive navigation is host-owned through an ordinary binding. Compose receives its native `WindowWidthSizeClass`, while HarmonyOS receives the finite enum. Device detection, font-scale branching and second navigation ownership are diagnostics, not approximate native fallbacks.

## 5. State and model boundary

The source remains ordinary SwiftUI. `RefractModel` is an empty marker protocol declared by the consuming iOS
application, not a linked framework; `docs/state-and-models.md` owns the model and observation details.

```swift
protocol SettingsModel: RefractModel {
    var title: String { get }
    var items: [SettingItem] { get }
    func save()
}

struct SettingsScreen: View {
    let model: SettingsModel
    @State private var draft: String = ""
    @Binding var isEnabled: Bool

    var body: some View { ... }
}
```

- `@State` accepts `Bool`, `Int`, `Double` and `String` with an explicit literal initializer. Compose uses
  `var draft by remember { mutableStateOf("") }`; ArkUI V2 uses `@Local private draft: string = ''`.
- `@Binding` has no initializer. Compose is a pair of `isEnabled: Boolean` and `onIsEnabledChange: (Boolean) -> Unit`;
  reads use the value and writes call the callback. ArkUI is `@Require @Param isEnabled: boolean` plus
  `@Event onIsEnabledChange: (value: boolean) => void`. Event callbacks have a safe no-op default only
  where ArkUI requires an initializer; required value parameters are never given fabricated values.
- `let model: <Protocol>` has no initializer. The protocol inherits the app-declared empty `RefractModel` marker and
  declares get-only scalar or typed-list properties and methods with scalar parameters. Methods return `Void`. The
  Kotlin boundary is an interface with `val title: State<String>` and direct methods; stability annotations follow
  the reviewed Compose stability contract, not a blanket promise of skippability. An existing app model implements
  that interface; no runtime adapter is created. Reads of `State` occur at the consuming leaf, not in a
  parameterless screen-level snapshot.
- The ArkTS `<Protocol>` is an interface with explicitly typed properties and methods. Its application implementation
  is `@ObservedV2`, with `@Trace` on each observed property. Collection properties used by `LazyForEach` satisfy the
  platform `IDataSource` contract. The component receives the model using `@Param @Require`. Model actions are
  invoked from event callbacks, so they do not become composition reads.
- `SettingItem` becomes an immutable Kotlin data class with `@Immutable`, and an explicitly typed ArkTS class using
  native observation annotations where item properties change. No generated singleton, service locator or mutable
  global state exists.
- The full parameter and property spelling is specified by `docs/state-and-models.md`; this section is the source
  contract and the required structural semantics. A platform limitation is a diagnostic, not a state-observation
  fallback.
- Two compile-time-only attribute markers extend the model boundary for forms: `@refractText` on a get-only String
  property lowers to a nullable native observable text, and `@refractAsync` on an action declares a native attempt
  returning `Boolean`/`boolean`. `docs/forms.md` owns the form declaration, submission and retry contract.

## 6. Diagnostics and fixture format

Codes are stable public API. Source, view, list, state, mapping and native diagnostics use
`RF<category><number>`: `SYN` is parsing/structure, `SEM` is source semantics, `VIEW` is a view or modifier,
`LIST` is list identity, `STATE` is state/models, `MAP` is mapping and `NATIVE` is native interop. Resource
failures use the established `R.string.*` namespace from `docs/localization.md`, so callers can distinguish a bad
key, a missing platform catalog and incompatible formatting. Each message names the construct, why it is unsupported
and a specific alternative. Do not renumber a code to change its wording.

An immediate directory of `Fixtures/` contains one self-contained input and its hand-written expectations:

```text
Input.swift
refract.json              optional; required when the case uses project mappings
Expected.kt               accepted case: complete hand-written Kotlin
Expected.ets              accepted case: complete hand-written ArkTS
Expected.diagnostics      rejected case: exact diagnostic lines, no expected native files
```

Diagnostics are one line per error, in source order, using the IR renderer's form:

```text
Input.swift:<line>:<column>: error [RF...]: <construct and reason> Suggestion: <specific alternative>
```

Line and column are one-based and point to the first character of the rejected construct. A rejected case has no
placeholder native files: generation fails atomically. `Fixtures/Corpus.json` lists every case by its `path` and
`implementationStatus`. `pending` identifies an agreed contract case whose owning backend is not ready; the runner
reports it explicitly as a known issue, never as a pass. `ready` requires exact golden regeneration. New cases begin
as pending unless the implementing PR also makes them pass. Updating a golden requires reviewing its handwritten
semantic contract and generated diff; there is no blind regeneration workflow.

A localized case's mapping declares its keys under both platform `resources.strings` tables. Its fixture also
