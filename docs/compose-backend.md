# Compose backend

The Compose backend turns the platform-neutral IR into idiomatic Jetpack Compose source. The output is ordinary
Kotlin that a reviewer could have written by hand: one `@Composable` function per SwiftUI `struct X: View`, plain
calls to the Android SDK and to the consuming app's design system, no Refract runtime dependency (goals 2, 3, 4).

This document is the contract for the emitted Kotlin. `docs/subset.md` owns which Swift constructs are accepted;
this page owns the exact Kotlin shape each accepted construct becomes, the performance rules the emitter must
honour, and the diagnostics the emitter raises for input it cannot translate faithfully. Every pattern shown here
has a golden fixture in `Fixtures/`.

## Responsibilities and boundaries

- **In scope.** Mapping IR views, modifiers, control flow and lists to Kotlin; choosing the `LazyColumn` keys and
  `contentType`; placing `remember` for lambdas and expensive values; emitting the file header; formatting the
  output deterministically; reporting coded diagnostics when the IR cannot be lowered without losing meaning.
- **Out of scope.** Deciding which Swift constructs are legal (`docs/subset.md`, #2), how `@State`/`@Binding` and
  model protocols look on the Kotlin side (#5 owns the observation design; this backend consumes the IR they
  define), the `refract.json` schema (#6), native component declarations (#7), localisation resources (#8),
  benchmark numbers (#9).

The emitter never invents names that are not derivable from the IR and `refract.json`. If lowering would need a
helper that is not part of the platform SDK or the app's declared design system, that is a design bug: stop and
open an issue rather than emitting a runtime shim (goal 2).

## Output shape

### File

One Kotlin file per Swift input file. The path is `<android-out>/<SwiftName>.kt`. The package and imports come
from `refract.json` (`android.package`, `android.imports`); the emitter adds only the imports it provably needs.

```kotlin
// Generated by Refract <version> from <Source>.swift. Do not edit.
@file:Suppress("RemoveRedundantQualifierName")

package com.example.generated

import androidx.compose.runtime.Composable
```

The header names the source file and the generator version so a reviewer can trace a generated file back to its
input. `Do not edit` is literal: hand edits are lost on the next `refract generate` (goal 1).

### Top-level composable

A `struct SettingsView: View` becomes a public `@Composable` function with the same name. Parameters are the
screen's declared inputs (model, `@Binding`s, design-system tokens the mapping injects); the function is callable
from any hand-written Android code with no host container (goal 4).

```kotlin
@Composable
fun SettingsView(model: SettingsModel, modifier: Modifier = Modifier) {
    // body
}
```

Rules:

- The function is `public` by default. `internal` Swift access maps to `internal`.
- `modifier: Modifier = Modifier` is the **first optional parameter** and is applied to the outermost container.
  This is the standard Compose convention and lets call sites customise placement without forking the screen.
- Parameters are value types, stable interfaces, or the model interface from #5. The emitter never captures a
  closure over unstable state at the top level; lambdas passed in are `@Composable`-clean (see "Performance
  rules").

### Containers

| SwiftUI | Compose | Notes |
| --- | --- | --- |
| `VStack(alignment:spacing:)` | `Column(modifier, verticalArrangement = Arrangement.spacedBy(s), horizontalAlignment = …)` | `spacedBy` is emitted only when `spacing` is non-zero. Default alignment `center` maps to `Alignment.CenterHorizontally`. |
| `HStack(alignment:spacing:)` | `Row(modifier, horizontalArrangement = Arrangement.spacedBy(s), verticalAlignment = …)` | Default alignment `center` maps to `Alignment.CenterVertically`. |
| `ZStack(alignment:)` | `Box(modifier, contentAlignment = …)` | The SwiftUI default `.center` maps to `Alignment.Center`; `.topLeading` to `Alignment.TopStart`. |
| `ScrollView` | `Column(Modifier.verticalScroll(rememberScrollState()))` for the vertical axis; `Row(Modifier.horizontalScroll(rememberScrollState()))` for horizontal | The scroll state is hoisted with `rememberScrollState()` so it survives recomposition. |
| `List` / `LazyVStack` over `ForEach` | `LazyColumn` | See "Lists". |

Nested containers compose structurally; the emitter never wraps a child in an extra `Box` "just in case".
A vertical `ScrollView` whose direct child is a `List` is rejected with `RF-C004`: nesting a lazy vertical list in a
vertical scroll container has no faithful finite-height Compose equivalent. Use the lazy list itself for that content.

### Leaf views

| SwiftUI | Compose |
| --- | --- |
| `Text("Hello")` | `Text(text = "Hello")` (literal) or `Text(text = stringResource(R.string.hello))` when the Swift side is a localisation key (#8). |
| `Text(model.title)` | `Text(text = model.title)` |
| `Image(systemName:)` | `RF-C002` unless a future typed symbol contract explicitly declares the Android icon. Use `Image("drawable_name")` → `Image(painter = painterResource(R.drawable.name), contentDescription = null)` with `android.resources.className`, or a declared native component. |
| `Button("Title") { … }` | `Button(onClick = { … }) { Text(text = "Title") }`. The action lambda is the IR's action body; the label becomes the slot. |
| `Toggle("Title", isOn: $flag)` | `Row { Text(text = "Title"); Spacer(Modifier.weight(1f)); Switch(checked = flag, onCheckedChange = { flag = it }) }`. The exact shape comes from #5's binding lowering; the backend composes it. |
| `TextField("Placeholder", text: $text)` | `TextField(value = text, onValueChange = { text = it }, placeholder = { Text(text = "Placeholder") })` |
| `Spacer()` | `Spacer(Modifier)` inside a `Row`/`Column`, or `Spacer(Modifier.weight(1f))` when the Swift side asks for flexible spacing. |
| `Divider()` | `HorizontalDivider()` inside a `Column`; `VerticalDivider()` inside a `Row`. |

Design-system components declared in `refract.json` map to the declared Kotlin call (#6). The emitter substitutes
argument labels per the mapping and fails with a diagnostic when a required parameter has no value.

### Static lists

A static `List` lowers to one `LazyColumn.item` per source row. Resource-keyed text rows and section headers have
unique source-derived keys and a `contentType`. Duplicate or non-portable derived text keys are rejected rather than
silently aliasing two rows. Model-property text rows use the declared property name. Static `TextField` and `Toggle`
rows use their state/binding declaration name in kebab-case, with a terminal `Enabled` suffix treated as the control's
form marker rather than part of the setting name (`displayName` → `display-name`, `notificationsEnabled` →
`notifications`). A static Button whose action is one zero-argument model method uses that method name; any other
action shape needs an explicit identity and is rejected. These are source-stable identities, not index fallbacks for a
dynamic model. `v0-settings-screen` demonstrates all four forms and the `row:save` action key.
`compose-typed-layout` demonstrates resource-text static sections and rows; `compose-scroll` demonstrates remembered
vertical scroll state; `compose-image` demonstrates a mapped application drawable. `Divider` and `Spacer` are emitted
directly in ordinary layouts.

### Modifiers

Modifiers attach to the `Modifier` chain of the view they decorate, in SwiftUI order. The first modifier in the
chain is the parameter `modifier` when the view is the root of the screen (so caller-supplied modifiers compose
correctly), otherwise `Modifier`.

| SwiftUI | Compose |
| --- | --- |
| `.padding()` | `Modifier.padding(all = Dp)` |
| `.padding(.horizontal, 16)` | `Modifier.padding(horizontal = 16.dp)` |
| `.padding(16)` | `Modifier.padding(all = 16.dp)` |
| `.frame(width:height:)` | `Modifier.size(width = …, height = …)`; `.frame(maxWidth: .infinity)` → `Modifier.fillMaxWidth()` |
| `.background(Color.red)` | `Modifier.background(Color.Red)` (colour tokens from the mapping when present) |
| `.foregroundColor(.red)` | `Text`'s `color = Color.Red` parameter, not a `Modifier` |
| `.font(.title)` | `Text`'s `style = MaterialTheme.typography.titleLarge` (token from the mapping) |
| `.cornerRadius(8)` | `Modifier.clip(RoundedCornerShape(8.dp))` |
| `.opacity(0.5)` | `Modifier.alpha(0.5f)` |
| `.onTapGesture { … }` | `Modifier.clickable { … }` (only where a clickable is valid; otherwise a diagnostic) |

A modifier that has no faithful Compose equivalent (for example `.listRowSeparator(.hidden)` on a non-list) is a
build-time diagnostic, never a silently dropped call (goal 3).

### Control flow

- `if condition { A } else { B }` becomes `if (condition) { A() } else { B() }` inside the composable body.
  Compose handles conditional composition natively; no wrapper is needed.
- Optional binding and associated-value patterns are rejected by the current typed subset (`RFCTRL002` and related
  diagnostics). A separate contract and typed lowering are required before either backend accepts them; no source-string
  substitution or runtime cast is used.
- `switch` over a locally declared enum without associated values, raw values or inheritance becomes a Kotlin `when`
  with exhaustive branches. A missing, duplicate or unsupported branch is a diagnostic, not a silent fallthrough.

### Lists

`List(items) { item in RowView(item: item) }` and `List { ForEach(items) { item in RowView(item: item) } }` both
become a `LazyColumn`. The two source forms share the same typed IR, identity validation and native output:

```kotlin
LazyColumn(modifier = modifier) {
    items(
        items = items,
        key = { it.id },
        contentType = { "RowView" }
    ) { item ->
        RowView(item = item)
    }
}
```

Performance rules baked into this shape (goal 2, `docs/performance.md`):

- **`key` is mandatory.** The IR must carry an identity key path; if the Swift side has no `Identifiable`
  conformance and no `id:` argument, the emitter raises a diagnostic instead of emitting a list without keys.
- **`contentType` is emitted** when every row in the list has the same static type. It lets Compose recycle
  composition across rows.
- The row lambda reads `item` directly; it never captures the outer collection, so a change to one row does not
  invalidate the whole list.
- Scroll position is hoisted with `rememberLazyListState()` only when the Swift side reads it; otherwise the
  default `LazyColumn` state is used to avoid an unnecessary allocation.

### State and bindings

The Kotlin shape of `@State`, `@Binding` and model protocols is owned by #5. This backend consumes the IR they
produce and follows two rules:

- Local `@State` becomes `var x by remember { mutableStateOf(initial) }` at the top of the composable.
- `@Binding` becomes a `(value: T, onValueChange: (T) -> Unit)` parameter pair so the parent owns the state.

Any observation helper the IR requires must come from the platform SDK (`androidx.compose.runtime`) or from the
app's own declared interfaces; the emitter never introduces a Refract-defined observable wrapper (goal 2).

## Performance rules

These are the rules the emitter enforces structurally. The catalogue in `docs/performance.md` (#9) is the source
of truth; each rule below names the fixture that demonstrates it.

1. **Stable parameters.** Composable parameters are value types, `Modifier`, or interfaces marked stable by the
   mapping. The emitter never passes a fresh lambda or a mutable collection directly as a parameter to a child
   composable without `remember`.
2. **Remembered lambdas.** A trailing lambda passed to a child composable is wrapped in `remember(key) { … }`
   when it captures a value that changes across recompositions, so the child can skip.
3. **No allocation in composition.** Constant values (`Dp`, `Color`, `Arrangement`, `Shape`) are referenced as
   top-level `private val`s in the generated file when they are used more than once; the emitter does not allocate
   them inside the composable body.
4. **Narrow state reads.** A `Text(model.title)` reads `model.title` at the call site, not via a derived holder,
   so Compose's snapshot system invalidates only the text that changed.
5. **List identity.** `LazyColumn` rows always carry a `key` and, when uniform, a `contentType`.
6. **No runtime.** The generated file imports only `androidx.*`, `kotlin.*`, the app's design-system package, and
   the model interfaces. There is no `import refract.*` (goal 2).

## Formatting and determinism

- Output is formatted with a single code writer that indents by 4 spaces, wraps parameter lists at one parameter
  per line when they exceed 100 columns, and emits trailing commas on multi-line calls (Kotlin style guide).
- The same IR and the same mapping produce byte-identical output on every machine. No timestamps, no host paths,
  no hash-ordering iteration: every collection the emitter walks is sorted by a stable key (declaration order,
  then name).
- The golden test runner regenerates every fixture and fails on any diff; updating expectations is a deliberate
  `refract generate --update` action, never a silent rewrite (goal 3).

## Diagnostics

The emitter reports a coded diagnostic with the source location and a suggested alternative. Initial codes the
Compose backend owns (the registry lives in `RefractIR`):

| Code | When | Suggestion |
| --- | --- | --- |
| `RF-C001` | A view or modifier has no Compose mapping and no `refract.json` entry | Declare the component in `refract.json` or use a supported view |
| `RF-C002` | `Image(systemName:)` (SF Symbol) | Use a drawable resource or a declared native component |
| `RF-C003` | A `ForEach` over data with no identity | Conform the element to `Identifiable` or pass `id:` |
| `RF-C004` | A modifier is applied where Compose has no equivalent (e.g. list-only modifier outside a list) | Remove the modifier or move it to the supported view |
| `RF-C005` | A `switch` is non-exhaustive | Add the missing cases or a `default` |
| `RF-C006` | Lowering would need a runtime helper (for example an untyped `Any` value) | Declare the type or use a native component |

A diagnostic is never downgraded to a warning to keep a build green: if the construct cannot be translated
faithfully, the build fails (goal 3).

## Testing

- Golden fixtures in `Fixtures/<case>/Expected.kt` for every construct above; the corpus is shared with #2 and the
  ArkUI backend (#4) so each Swift input has both expected outputs side by side.
- Unit tests in `Tests/RefractComposeTests` cover the code writer (indentation, trailing commas, determinism) and
  each diagnostic code.
- The Android example (#10) compiles the generated Kotlin with Gradle; where the SDK is unavailable the PR says so.

## Open decisions

- Exact `Modifier` chain ordering when several SwiftUI modifiers commute in Compose but not in SwiftUI (recorded
  per-modifier above; resolved case by case with fixtures).
- Whether the emitter hoists repeated `Dp`/`Color` constants into `private val`s always or only above a usage
  threshold. Initial choice: only when used more than once, to keep small files readable.
